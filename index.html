How to read this report
Three-hour protection: each station is designed to hold enough bins for Stores to replenish before production runs out. Working time excludes 09:55–10:15, 12:55–13:30 and non-working days. High call frequency shows demand cadence, not failure. A true sizing comparison additionally needs planned bike build, bins at station and consumption per bike from the Kanban simulator.

About This Report

Operational browser report. Transaction data stays in the connected local or SharePoint-synchronised files and is not stored in GitHub.

What it does

  • Groups Kanban requests into Area, Sub-area, Rack and Column levels from the connected Area Config.
  • Aging uses a working-hours calendar that matches the real shift pattern — Monday to Thursday by default, with Friday handled per Area via a logged exception.
  • Lets you export a pick list with scannable QR or Code128 barcodes straight from any Area.
  • Trends and Item Analysis show demand flow and whether Stores protected production inside the three-working-hour replenishment window.

Day to day use

  • Connect the Kanban export, Area Config and Production Calendar once in Chrome or Edge. Use silent refresh or the five-minute TV refresh for updated files.
  • Area grouping is controlled entirely by the Area Config file — edit it in Excel and re-connect to regroup instantly.
  • Production Calendar exceptions are logged with who and when, so a one-off Friday shift never silently changes any other date.
  • On the Trends page, click any bar to see that period's figures and a full item breakdown below it, the same way the Item Analysis page works.
  • Daily trends can cover one month or several months; Weekly uses a from/to date range. Export Excel + chart downloads the visible trend.
  • Picker Performance has a range, picker and active-date selector. Download Excel includes range, daily and hourly detail.

Working-time rules

  • Monday–Thursday, 07:00–16:30. Breaks 09:55–10:15 and 12:55–13:30 are excluded. Friday is included only through an Area calendar exception.

Engineering interpretation

  • High call frequency is Kanban demand cadence, not a failure. The station bins are designed to protect production for three hours while Stores replenishes.
  • A transaction reaching 180 working minutes is a replenishment risk; download the exact transactions from Item Analysis.
  • To test bin sizing, connect planned bike build, consumption per bike and station bin storage from the Kanban simulator. Mixed-item quantity totals are intentionally excluded.

QR / Barcode pick lists

  • Codes are generated entirely inside this file — no internet connection needed, and they've been checked to scan correctly.
